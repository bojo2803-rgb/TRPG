## 1. 目的

GM（自分）が TRPG の世界設定を作り、整理するための補助アプリ。

- まとめたい情報：NPC、時系列、ロケーション、アイテム、勢力、ストーリーの流れ
- 自動生成はしない
- AIアシスタント連携（チャットで付箋をつないでもらう等）は将来の構想。**今回は作らない**

## 2. 利用環境（決定済み）

| 項目 | 決定内容 |
|---|---|
| 使う人 | 自分だけ |
| 端末 | 複数（PC＋スマホ／タブレット） |
| PCでできること | 全機能 |
| スマホでできること | 閲覧＋軽い追記（付箋を読む・新しく足す） |
| 形態 | ブラウザで開くWebアプリ |
| 保存 | データはブラウザの中に保存し、自分のGoogleドライブと同期する（B案）。電波がなくても動く |

検討して見送った案：
- Supabase（クラウドのデータベース）：手早く作れるが、1週間使わないと一時停止する
- Obsidianを土台にする：作る量は最小だが、付箋の連動が Obsidian の作りに縛られる

## 3. 基本の考え方：付箋と線

- **付箋**：どんなアイデアでも書ける1枚。種類は固定しない。タグと色で整理する（「NPC」「場所」なども付箋に付けるタグの1つ）
- **線**：付箋どうしをつなぎ、関係を表す（例：「親子」「敵対」「所属」）
- **一度書けば使い回せる**：同じ付箋を、次のどの場所にも貼れる。貼っても中身は1つだけで、どこで直してもすべてに反映される
  1. ボード（自由に並べるキャンバス）
  2. 時系列マップ（§4）
  3. 地図
  4. ほかの付箋のメモ欄（付箋の中に付箋を貼る）

## 4. 時系列マップ

### 4.1 しくみ

時間は、点と線でできたノンリニアなグラフとして描く。

- **時点**：マップ上の点
- **時間の流れ**：時点と時点をつなぐ線。線はそれぞれ自分の長さ（経過時間）を持つ
- **本線**：暦と結びついた基準の線（例：西暦）

線の形で、いろいろな時間の現象を表す。

| 線の形 | 意味 |
|---|---|
| 本線から分かれて、後で本線に戻る | 体感時間の違い（浦島効果など） |
| 分かれたまま戻らない | 世界線の分岐 |
| 本線とつながらない別の線 | パラレルワールド |
| 元の時点に戻る輪 | タイムループ |
| 過去に戻る矢印 | タイムトラベル |
| 別の世界線へ渡る矢印 | 世界線移動 |

浦島効果の考え方：体感の違う主体の経験は「分岐」として描き、その分岐はいずれ本線に合流する。竜宮城の3年間は、本線の720年から分かれて1020年で合流する、長さ3年の枝になる。

### 4.2 付箋を時間に置く

- 付箋は、時系列マップ上の時点から線を伸ばしてつなぐ
- 日付がはっきりしない付箋も扱えるようにする（§5.3）

### 4.3 主体と視点の切り替え（歪み）

- どの付箋も「主体」になれる。主体は、時系列マップ上で自分が通った**道筋**を持つ
- 主体を選ぶと、その主体の道筋が**まっすぐな1本**になり、本人が体感した長さで伸び縮みする
- ほかの線はそれに引っ張られて伸び縮みし、マップ全体が歪む（アニメーションで変形する）
- 縮んだ線は波線、伸びた線は色を変えて、歪みの大きさが一目でわかるようにする
- ループしている主体を選ぶと、ループの輪が周回数の分だけ大きく膨らむ
- 何も選んでいないときは、本線の視点（本線がまっすぐ、長さは暦どおり）

```
[本線の視点] 本線がまっすぐ。長さは西暦どおり
 700 ── 720 ━━━━━━━━ 300年 ━━━━━━━━ 1020 ── 1070
          ╲                          ╱
           ╰── 竜宮城（3年）──────────╯   ← 3年分しかないのに引き伸ばされる

[浦島太郎の視点] 本人の道筋がまっすぐ。長さは体感どおり
 700 ── 720 ── 竜宮城（3年）── 1020 ── 1070
          ╲〰〰〰〰〰〰〰〰〰〰〰╱
            本線の300年                 ← ぎゅっと縮んで波打つ
```

### 4.4 まとめる・絞り込む

- **まとめ**：複数の出来事をまとめて、「シナリオ名」を付けた1つの出来事として扱える
  - たたむと1つの点に、ひらくと中身の出来事が見える
  - まとめ自体も1枚の付箋として扱い、線でつないだり、ほかの場所に貼ったりできる
- **絞り込み**：あるタグの付いた要素を除外する、そのタグだけを表示する、など
- ほかの絞り込み方の候補は §9 の Q9

## 5. 暦と日付

### 5.1 基本方針

1. **日付は「日の通し番号」で記録する**
   - 天文学で使う「ユリウス通日」という、日に振った通し番号で記録する
   - どの暦で見せるかは、画面に出すときに変換する。これで、保存したデータ自体が暦の流派に左右されない
2. **ブラウザに入っている暦変換は、正確さの根拠にしない**
   - ブラウザ内蔵の和暦変換は、元号を付けるだけで月日は太陽暦のまま。そのため明治5年以前の日付は実際の旧暦とずれる（西暦720年1月15日を「養老4年」と出すが、旧正月前なので正しくは養老3年）
   - 新しい日付の仕組み（Temporal）は、Chrome 144・Firefox 139 以降では使えるが、調査時点のSafariでは試験版のみ。iPhoneで使えない可能性がある
   - なので変換は自前で作り、ブラウザ内蔵の変換はテストで答え合わせする相手として使う
3. **正解が1つに決まらない日付は、そう表示する**
   - 黙ってどれか1つを選ばず、「この日は流派によって◯日ずれる」と画面に出す
   - 流派は設定で切り替えられるようにする
4. **公表されている対照表と突き合わせるテストを作る**

### 5.2 暦ごとの選択肢

各暦について、正確に決まる範囲と、流派が分かれる点を挙げる。★は推奨案。

#### (a) 西暦

| 論点 | 選択肢 |
|---|---|
| ユリウス暦とグレゴリオ暦の切り替え | ★A. 1582年10月15日で切り替え（歴史学の一般的な慣例）<br>B. 国・地域ごとの切り替え日を選べる（イギリス1752年、日本1873年、ロシア1918年、ギリシャ1923年など）<br>C. 全期間グレゴリオ暦で計算（先発グレゴリオ暦。ISO 8601 と同じ）<br>D. 全期間ユリウス暦で計算 |
| 紀元前の数え方 | ★A. 歴史式（紀元前1年の次が紀元1年。0年はない）<br>B. 天文式（0年があり、紀元前1年＝0年、紀元前2年＝−1年） |
| 年の始まり | ★A. 1月1日<br>B. 地域の旧習に合わせる（例：イングランドは1752年まで3月25日が年始）。この場合「1714/15年」のように二重に表記する |

計算だけで正確に出せる。流派の違いはあっても、流派を決めれば答えは1つに決まる。

#### (b) 和暦（元号＋旧暦）

期間ごとに、正確さの根拠が違う。

| 期間 | 根拠 | 正確さ |
|---|---|---|
| 明治6年（1873年）以降 | 元号＋グレゴリオ暦 | 計算で正確 |
| 7世紀末〜明治5年 | 実際に使われた暦法（元嘉暦・儀鳳暦・大衍暦・五紀暦・宣明暦・貞享暦・宝暦暦・寛政暦・天保暦）による暦日。専門家が編纂した対照表（内田正男『日本暦日原典』1975年が標準）に基づく | 対照表どおりなら正確 |
| それより前（神武天皇〜） | 『日本書紀』の日付を、後の時代の暦法でさかのぼって計算した復元（小川清彦の研究）。**史実ではなく伝承上の暦日** | 復元値 |

データの入手元の選択肢：

| 案 | 内容 | 注意点 |
|---|---|---|
| ★A | jcalendaR（和暦・旧暦・西暦を相互変換するRのパッケージ。MITライセンス）のデータを使う | データの出典を確認する必要あり |
| ★B | 国立天文台「日本の暦日データベース」（神武天皇〜）を参照して表を作る | 利用条件の確認が必要 |
| C | 各暦法の計算式を自分で実装する | 手間が非常に大きく、検証も難しい |
| D | 書籍（『日本暦日原典』など）から手で入力する | 現実的ではない |

推奨：A か B を元データにし、もう一方と突き合わせて検証する。

そのほかの論点：

| 論点 | 選択肢 |
|---|---|
| 南北朝時代（1331〜1392年ごろ）の元号 | ★A. 北朝と南朝を併記する（南朝を先に書く慣例）<br>B. 北朝のみ<br>C. 南朝のみ |
| 改元した年の扱い | A. 改元した日から新元号に切り替える（実際の運用どおり）<br>B. その年の1月1日にさかのぼって新元号にする（年表でよく使われる慣例）<br>★C. A を基本にして、B も併記する |
| 伝承期間（神武天皇〜）の日付 | ★A. 「伝承上の暦日」と注記して表示する<br>B. 表示しない |
| そのほかの表記 | 干支、皇紀（神武天皇即位紀元＝西暦−660年） |

**明治6年以降の「旧暦」**（公式ではないが、六曜などで今も使われている）：

- 天保暦の方式に、現代の天文計算（朔と二十四節気）を当てはめて計算する。基準は日本時間（東経135度）
- 中国・韓国・ベトナムの旧暦は、基準にする経度が違うため、日本の旧暦と日付がずれる日がある
- **2033年問題**：2033〜2034年は、天保暦の決まりでは閏月の位置が決められない。どれを選んでも規則のどこかに反する

| 選択肢 | 内容 |
|---|---|
| A | 閏11月にする |
| B | 閏7月にする |
| C | 閏1月（2034年）にする |
| ★D | 「決定不能」と表示し、A〜C を併記する |

- 日本カレンダー暦文化振興協会が「2033年旧暦閏月問題の見解」を出している。ただし、どの案を支持しているかはまだ原典で確認できていない
- 確認できたら、その案を初期設定にする。それまでは D にしておく

#### (c) ヒジュラ暦（イスラム暦・太陰暦）

本来は、三日月を目で見て月の始まりを決める。そのため国や流派によって1〜2日違い、世界共通の正解がない日がある。

| 案 | 内容 | 範囲 |
|---|---|---|
| A | ウンム・アル＝クラー暦（サウジアラビア公式の計算暦） | 公式の対照表があるのは1356〜1500 AH（1937〜2076年） |
| B | 表形式ヒジュラ暦（計算式）。30年周期の閏年の置き方4種類（15型・16型〔最も一般的〕・インド型・ハバシュ・アル＝ハースィブ型）×紀元日2種類（622年7月15日・7月16日） | 全期間 |
| C | トルコ（宗務庁）の計算暦 | 現代 |
| D | 東南アジア（MABIMS基準）の計算暦 | 現代 |
| E | 各国の実際の目視記録 | まとまった公的データがない |

- ★推奨：1937〜2076年は A、それ以外は B（16型・7月16日紀元）。B の範囲では「±1〜2日の不確かさ」と表示する
- 1日の始まり：本来は日没。★A. 深夜0時で区切る（簡略）／B. 日没で区切る（場所の指定が必要）

#### (d) イラン暦（ヒジュラ太陽暦）

- 公式には、テヘランの子午線で春分を天文計算して年の始まりを決める
- 33年周期の計算式は、1925〜2088年の範囲で公式と一致する
- 2820年周期の計算式（ビーラシュク案）は、2025年にすでに公式とずれる

| 案 | 内容 |
|---|---|
| ★A | 天文計算で公式どおりに出す |
| B | 33年周期の計算式を使い、1925〜2088年以外は注記を付ける |

#### (e) 中国の旧暦（農暦）

- 1645年（時憲暦）より前は暦法が何度も変わっており、現代の天文計算を過去に当てはめても史実とは一致しない
- ブラウザ内蔵の中国暦は現代の計算方法なので、古い時代には使えない

| 案 | 内容 |
|---|---|
| A | 史実の暦日の対照表を使う（データ元は要調査） |
| B | 現代の天文計算でさかのぼり、「史実と異なる可能性」と注記する |

韓国・ベトナムの旧暦も同じ構造。基準にする経度が違うので、中国の旧暦と日付がずれる日がある。

#### (f) ユダヤ暦

- 現在の計算規則は10世紀ごろまでに確定し、それ以降は計算で正確
- それより前の日付は、後の規則を過去に当てはめた推算。当時実際に目視で決めていた日付とは違いうる
- 1日の始まりは日没（ヒジュラ暦と同じ論点）

| インド国定暦（サカ暦） | 計算で正確 |

#### (h) 架空の暦

TRPGなので、独自の暦（月の数・名前・日数、曜日、紀元）を定義できるようにするかどうか → §9 の Q17

### 5.3 日付の入力

- 精度：年だけ／月まで／日まで／時刻まで
- あいまいさ：「〜頃」、「AとBの間のどこか」
- 日付がない出来事も、前後関係だけを線で示せる
- 分岐の長さ（体感時間）は、年・日・時間などの単位で入れる

## 8. 作る順番（案）

時系列マップと暦は一番複雑なので、先に「付箋と線」の土台を作ってから載せる。

1. 付箋・線・ボード＋ブラウザ内保存
2. Googleドライブ同期
3. 時系列マップ（本線・分岐・合流・歪み表示・まとめ・絞り込み）

## 9. 質問（未回答）

わからないもの・どちらでもいいものは飛ばして構わない。その場合は【推奨】の案で進める。

### 付箋・ボード

- **Q1.** 付箋に書ける内容は？ 文字だけ／書式（見出し・太字・箇条書き）／画像／本文中に別の付箋へのリンク
  - 【推奨】全部入り
- **Q2.** NPCの「年齢・所属」のように、タグごとに決まった入力欄（テンプレート）を作りたい？ それとも自由記述だけで十分？
- **Q3.** 線に向き（矢印）は必要？ ラベル、色、線の種類（点線など）は？
  - 【推奨】全部できるようにする
- **Q4.** ボードは1枚？ テーマごとに何枚も作る？
  - 【推奨】何枚も
- **Q5.** 「まとめ」（§4.4）はボード上でも使いたい？（付箋を枠で囲んで1つにたたむ）
- **Q6.** 世界（キャンペーン）は1つだけ？ 複数の世界を別々に管理したい？
  - 【推奨】複数。世界ごとにファイルを分ける

### 時系列マップ

- **Q7.** 「選んだ主体の道筋がまっすぐになり、ほかが歪む」見せ方（§4.3）で合っている？
- **Q8.** まとめの入れ子（シナリオの中に章、章の中に場面……）は何段まで必要？
  - 【推奨】何段でも
- **Q9.** 絞り込みは、ほかに何が欲しい？ 候補：
  - 選んだ主体に関係するものだけ表示
  - 期間で絞る
  - キーワード検索で該当箇所を光らせる
  - 世界線ごとの表示／非表示
- **Q10.** 自動の配置が見づらいとき、手で位置を直したい？
  - 手で直すと、主体を切り替えたときの自動変形とぶつかる。直した位置は「本線の視点」でだけ使う、などの決めごとが必要になる
- **Q11.** タイムトラベルで過去に戻り、同じ時期をもう一度生きる主体。2回目は「分岐」として描く、で合っている？（「体感の違いは分岐」の考え方の延長）
- **Q12.** 同じ人物が同時に2か所にいる場合（分身、並行世界の同一人物）の扱いは？
  - A. 別々の付箋にして「同一人物」の線でつなぐ
  - B. 1枚の付箋が複数の道筋を持つ
- **Q13.** 因果の矛盾（親殺しのパラドックスなど）を警告してほしい？ それとも自由に描けるだけでいい？
  - 【推奨】警告なし
- **Q14.** 時間の規模は？
  - 数十年〜数千年くらいか、宇宙規模（数十億年）まであるか
  - 1つのマップで「分・秒単位」と「億年単位」を混ぜるか
  - 両方を1つのマップで扱う場合は、記録の仕方を工夫する必要がある

### 暦・日付

- **Q15.** 最初に使えるようにしたい暦は？（西暦・和暦・ヒジュラ暦のほかに、§5.2 の (d)〜(g) で要るもの）
- **Q16.** §5.2 の★（推奨案）を初期設定にしてよい？ 変えたいものはある？
