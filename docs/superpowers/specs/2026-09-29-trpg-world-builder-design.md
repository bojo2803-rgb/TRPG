## 1. 目的

GM（自分）が TRPG の世界設定を作り、整理するための補助アプリ。

- メインで遊ぶシステム：クトゥルフ神話TRPG（CoC）
- まとめたい情報：NPC、時系列、ロケーション、アイテム、勢力、ストーリーの流れ
- 設定の自動生成はしない。ただし、発想のきっかけとして「マルコフ連鎖でランダムなキャラクターを出す機能」は後で追加する候補（§9 Q36）
- AIアシスタント連携は将来の構想。**今回は作らない**

## 3. 付箋とボード

### 3.1 付箋

- どんなアイデアでも書ける1枚。種類は固定せず、タグと色で整理する
- 書ける内容：文字、書式（見出し・太字・箇条書き）、画像、本文中から別の付箋へのリンク
- **テンプレート**：タグごとに決まった入力欄を持たせられる
  - 例：CoCの探索者・NPC用に、能力値、技能、所属、年齢、生年月日など
  - テンプレートは画面上で自分で作り、直せる（コード不要）
  - CoC用のひな形を最初から用意する（版は §9 Q35）。ルールブックの本文は入れず、項目名と初期値の枠だけを用意する

### 3.2 線（付箋どうしのつながり）

- ラベル、色、線の種類（実線・点線など）を付けられる
- ボード上の線の矢印は「付けても付けなくてもいい」扱いにする（仮決め）
- 時系列マップの線には矢印を使わない（§4.1）

### 3.3 ボード

- ボードは自由に何枚でも追加できる
- キャラクター、出来事、ロケーション、シナリオなどの付箋は、**それぞれ専用のボードを持てる**。付箋を開くと、そのボードが出てくる
- 1枚の付箋を、いくつものボードに貼れる。中身は1つだけで、どこで直してもすべてに反映される
- ボードの種類：

| 種類 | 内容 |
|---|---|
| コルクボード | 付箋を自由に並べ、アイデアや概念を自由につなぐ |
| 家系図 | 親子・婚姻などの関係から、自動で家系図の形に並べる |

### 3.4 まとめ（親子関係）

- 付箋どうしに「親子」の関係を付けられる。シナリオ → 章 → 場面、のような入れ子に使う
- 親も子も何人いてもよい。循環（パラドックス）が起きてもよい
- ボード上でも、時系列マップ上でも使える。たためば1つにまとまり、ひらけば中身が見える
- たたむときの決まり（案）：たたんだまとめの子孫は隠す。ただし、別の開いているまとめにも属していれば表示する。循環していても無限にたどらないようにする

### 3.5 グラフビュー

- すべての付箋とつながりを、Obsidian のグラフビューのような網の目で表示する
- 親子関係のように、ピラミッド型では描けないつながりを見渡すのに使う

## 4. 時系列マップ

### 4.1 しくみ

時間は、点と線でできたノンリニアなグラフとして描く。

- **時点**：マップ上の点
- **時間の流れ**：時点と時点をつなぐ線。どの線も**左から右へ流れる**。矢印は使わない
- **本線**：暦と結びついた基準の線（西暦）
- 線の上にカーソルを合わせると、その位置の日時（西暦の年月日）が出る。分岐や逆行があっても、日時を見れば時間の流れがわかる

| 線の形 | 意味 |
|---|---|
| 本線から分かれて、後で本線に戻る | 体感時間の違い（浦島効果など） |
| 分かれたまま戻らない | 世界線の分岐 |
| 本線とつながらない別の線 | パラレルワールド、ドリームランドのような別の世界 |
| 元の時点に戻る輪 | タイムループ |
| 過去の時点へ渡る | タイムトラベル |
| 別の世界線へ渡る | 世界線移動 |

### 4.2 時間の長さの表し方

- **宇宙の始まりから**すべてを表せる
- 何も起きていない区間は、どれだけ長くても短く縮めて描き、「≈ 92億年」のような省略の印を付ける。どの主体の視点でも同じ
- 最小の単位は「分」。記録の仕組みは秒にも対応させておき、必要になったら画面に出す（§5.4）

### 4.3 主体と視点の切り替え（歪み）

「動くものを使ってみないと断言できないが、合っていると思う」との回答。**試作品で確かめる**（§10）。

- どの付箋も「主体」になれる。主体は、時系列マップ上で自分が通った**道筋**を持つ
- 主体を選ぶと、その主体の道筋が**まっすぐな1本**になり、本人が体感した長さで伸び縮みする
- ほかの線はそれに引っ張られて伸び縮みし、マップ全体が歪む（アニメーションで変形する）
- 縮んだ線は波線、伸びた線は色を変えて、歪みの大きさが一目でわかるようにする
- 何も選んでいないときは、本線の視点

```
[本線の視点] 本線がまっすぐ。長さは西暦どおり
 700 ── 720 ━━━━━━━━ 300年 ━━━━━━━━ 1020 ── 1070
          ╲                          ╱
           ╰── 竜宮城（3年）──────────╯   ← 3年分しかないのに引き伸ばされる

[浦島太郎の視点] 本人の道筋がまっすぐ。長さは体感どおり
 700 ── 720 ── 竜宮城（3年）── 1020 ── 1070
          ╲〰〰〰〰〰〰〰〰〰〰〰╱
            本線の300年                 ← ぎゅっと縮んで波打つ
```

- 配置はすべて自動。**手で位置を直す必要がないように作る**

### 4.4 タイムトラベルとパラドックス

- 過去に戻ってパラドックスが起きた場合は、そこで世界線が分岐する
- パラドックスが起きなければ、同じ世界線の同じ時期をもう一度生きる
  - この場合、主体の道筋は同じ線を2回通る。「道筋をまっすぐにする」表示とぶつかるため、描き方は試作品で決める
  - 案：本人の生涯線を別に1本まっすぐ引き、世界の線はどちらか一方の通過位置に寄せる。もう一方の通過位置とは細い線でつなぐ
- タイムループの輪は、ループしている主体の視点では、周回数の分だけ大きく膨らむ
- **イースターエッグ**：パラドックスが起きそうな状況で、遊び心のある警告を出す（案は §9 Q39）

### 4.5 同じ人物が2人いる場合

- 分身や、並行世界の同一人物は、「NPC1A」「NPC1B」のように別々の人物（別々の付箋）として扱う

### 4.6 絞り込み

- あるタグの付いた要素を除外する／そのタグだけを表示する
- 選んだ主体に関係するものだけを表示する
- 期間で絞る
- キーワード検索で該当箇所を光らせる
- 世界線ごとに表示／非表示を切り替える

## 5. 暦と日付

### 5.1 基本方針

- **基本は西暦で表す**
- 出来事ごとに、その性質に合わせて別の暦を追加して表示できる（例：昔の日本の事件には和暦を追加）。すべての出来事にすべての暦を載せることはしない
- 日付はどの暦でも入力できる。入力に使った暦は、自動でその出来事の追加暦になる
  - 例：史料に「天正10年6月2日」とあれば、和暦のまま入力する。西暦（ユリウス暦1582年6月21日）に正しく変換され、和暦も併せて表示される
- 正確さにこだわる理由：昔の日本の出来事は太陰太陽暦（旧暦）で記録されていることが多く、変換がずれると西暦で並べたときに前後関係が崩れるため
- 正解が1つに決まらない日付は、黙ってどれか1つを選ばず、そう表示する
- 公表されている対照表と突き合わせるテストを作る
- ブラウザに入っている暦変換は、正確さの根拠にしない（明治5年以前の和暦を太陽暦の月日のまま出してしまう。新しい日付の仕組み Temporal は、調査時点の Safari では試験版のみ）。変換は自前で作り、ブラウザ内蔵の変換はテストの答え合わせにだけ使う

### 5.2 使える暦

| 暦 | 時期 |
|---|---|
| 西暦 | 最初から |
| 和暦（元号＋旧暦） | 最初から |
| ヒジュラ暦 | 最初から |
| 架空の暦（独自の月名・月数・日数・曜日・紀元） | 自分で追加できるようにする |
| そのほか（§5.5 (d)） | 必要になったら追加 |

各暦の流派は §5.5 の★（推奨案）を初期設定にする。

**分岐した時間の暦**
- 浦島効果などで引き伸ばされた分岐の中では、分岐した時点から西暦を数え直し、「西暦の一種」であることがわかる表記にする（表記の案は §9 Q37）
- 例：竜宮城の分岐（本線の720年に分岐し、1020年に合流、体感3年）の中では「720年〜723年」と数え、別の表記を付けて本線の西暦と区別する

**ドリームランド**
- 現実とは時間の流れ方が違う別の世界として、専用の暦を持たせる
- 現実の時間との対応は一対一ではない。ドリームランドの線は本線とつながらない別の線にし、夢見る者が出入りした時点だけが現実とつながる

### 5.3 時刻とタイムゾーン

- 時刻は分まで入力できる
- タイムゾーンを使える。初期設定は**日本標準時**
- 出来事ごとにタイムゾーンを指定できる（例：ロンドンの事件はロンドン時間で入力・表示）
- 歴史上の時差（日本標準時ができる1888年より前の地方時など）は、国際的に使われているタイムゾーンのデータベースに従う。そのデータベースが扱える範囲より前（数十万年より前など）は、決まった時差で計算する

### 5.4 内部の記録方法

- 日時は「**日の通し番号（整数）**」と「**その日の中の秒数（整数）**」の2つの数で記録する
  - 画面は分単位で表示する。秒を表示したくなったら、画面を変えるだけで済む
- この方式なら、宇宙の始まり（約138億年前）の日付でも秒まで正確に持てる
  - 1つの数で秒まで数えようとすると、ブラウザで正確に扱える数の上限を超える
- 暦の変換は、極端に大きい年（紀元前138億年など）でも正しく計算できるように作る

### 5.5 暦ごとの選択肢

各暦について、正確に決まる範囲と、流派が分かれる点を挙げる。★は推奨案で、初期設定にする。

#### (a) 西暦

| 論点 | 選択肢 |
|---|---|
| ユリウス暦とグレゴリオ暦の切り替え | ★A. 1582年10月15日で切り替え（歴史学の一般的な慣例）<br>B. 国・地域ごとの切り替え日を選べる（イギリス1752年、日本1873年、ロシア1918年、ギリシャ1923年など）<br>C. 全期間グレゴリオ暦で計算（先発グレゴリオ暦。ISO 8601 と同じ）<br>D. 全期間ユリウス暦で計算 |
| 紀元前の数え方 | ★A. 歴史式（紀元前1年の次が紀元1年。0年はない）<br>B. 天文式（0年があり、紀元前1年＝0年、紀元前2年＝−1年） |
| 年の始まり | ★A. 1月1日<br>B. 地域の旧習に合わせる（例：イングランドは1752年まで3月25日が年始）。この場合「1714/15年」のように二重に表記する |

計算だけで正確に出せる。流派の違いはあっても、流派を決めれば答えは1つに決まる。

#### (b) 和暦（元号＋旧暦）

期間ごとに、正確さの根拠が違う。

| 期間 | 根拠 | 正確さ |
|---|---|---|
| 明治6年（1873年）以降 | 元号＋グレゴリオ暦 | 計算で正確 |
| 7世紀末〜明治5年 | 実際に使われた暦法（元嘉暦・儀鳳暦・大衍暦・五紀暦・宣明暦・貞享暦・宝暦暦・寛政暦・天保暦）による暦日。専門家が編纂した対照表（内田正男『日本暦日原典』1975年が標準）に基づく | 対照表どおりなら正確 |
| それより前（神武天皇〜） | 『日本書紀』の日付を、後の時代の暦法でさかのぼって計算した復元（小川清彦の研究）。**史実ではなく伝承上の暦日** | 復元値 |

データの入手元の選択肢：

| 案 | 内容 | 注意点 |
|---|---|---|
| ★A | jcalendaR（和暦・旧暦・西暦を相互変換するRのパッケージ。MITライセンス）のデータを使う | データの出典を確認する必要あり |
| ★B | 国立天文台「日本の暦日データベース」（神武天皇〜）を参照して表を作る | 利用条件の確認が必要 |
| C | 各暦法の計算式を自分で実装する | 手間が非常に大きく、検証も難しい |
| D | 書籍（『日本暦日原典』など）から手で入力する | 現実的ではない |

推奨：A か B を元データにし、もう一方と突き合わせて検証する。

そのほかの論点：

| 論点 | 選択肢 |
|---|---|
| 南北朝時代（1331〜1392年ごろ）の元号 | ★A. 北朝と南朝を併記する（南朝を先に書く慣例）<br>B. 北朝のみ<br>C. 南朝のみ |
| 改元した年の扱い | A. 改元した日から新元号に切り替える（実際の運用どおり）<br>B. その年の1月1日にさかのぼって新元号にする（年表でよく使われる慣例）<br>★C. A を基本にして、B も併記する |
| 伝承期間（神武天皇〜）の日付 | ★A. 「伝承上の暦日」と注記して表示する<br>B. 表示しない |
| そのほかの表記 | 干支、皇紀（神武天皇即位紀元＝西暦−660年） |

**明治6年以降の「旧暦」**（公式ではないが、六曜などで今も使われている）：

- 天保暦の方式に、現代の天文計算（朔と二十四節気）を当てはめて計算する。基準は日本時間（東経135度）
- 中国・韓国・ベトナムの旧暦は、基準にする経度が違うため、日本の旧暦と日付がずれる日がある
- **2033年問題**：2033〜2034年は、天保暦の決まりでは閏月の位置が決められない。どれを選んでも規則のどこかに反する

| 選択肢 | 内容 |
|---|---|
| A | 閏11月にする |
| B | 閏7月にする |
| C | 閏1月（2034年）にする |
| ★D | 「決定不能」と表示し、A〜C を併記する |

- 日本カレンダー暦文化振興協会が「2033年旧暦閏月問題の見解」を出している。ただし、どの案を支持しているかはまだ原典で確認できていない
- 確認できたら、その案を初期設定にする。それまでは D にしておく

#### (c) ヒジュラ暦（イスラム暦・太陰暦）

本来は、三日月を目で見て月の始まりを決める。そのため国や流派によって1〜2日違い、世界共通の正解がない日がある。

| 案 | 内容 | 範囲 |
|---|---|---|
| A | ウンム・アル＝クラー暦（サウジアラビア公式の計算暦） | 公式の対照表があるのは1356〜1500 AH（1937〜2076年） |
| B | 表形式ヒジュラ暦（計算式）。30年周期の閏年の置き方4種類（15型・16型〔最も一般的〕・インド型・ハバシュ・アル＝ハースィブ型）×紀元日2種類（622年7月15日・7月16日） | 全期間 |
| C | トルコ（宗務庁）の計算暦 | 現代 |
| D | 東南アジア（MABIMS基準）の計算暦 | 現代 |
| E | 各国の実際の目視記録 | まとまった公的データがない |

- ★推奨：1937〜2076年は A、それ以外は B（16型・7月16日紀元）。B の範囲では「±1〜2日の不確かさ」と表示する
- 1日の始まり：本来は日没。★A. 深夜0時で区切る（簡略）／B. 日没で区切る（場所の指定が必要）

#### (d) 必要になったら追加する暦の候補

| 暦 | 正確さ・流派 |
|---|---|
| イラン暦（ヒジュラ太陽暦） | 公式はテヘランの子午線で春分を天文計算して決める。33年周期の計算式は1925〜2088年の範囲で公式と一致。2820年周期の計算式は2025年にすでにずれる |
| 中国の旧暦（農暦） | 1645年より前は暦法が何度も変わっており、現代の天文計算を過去に当てはめても史実と一致しない。史実の対照表が必要 |
| 韓国・ベトナムの旧暦 | 中国と同じ構造。基準の経度が違うので日付がずれる日がある |
| ユダヤ暦 | 10世紀ごろ以降は計算で正確。それより前は推算 |
| エチオピア暦・コプト暦・インド国定暦・タイ仏暦・民国紀年 | 計算で正確 |
| ヒンドゥー暦 | 地域と流派で多数に分かれる |
| マヤ長期暦 | 西暦との対応に流派がある（GMT相関 584283 が標準、ほかに 584285、ベーム相関 622261） |
| フランス革命暦 | 年始の決め方が2通り（本来の春分基準／ロム案の計算式） |

### 5.6 あいまいな日付

- 精度：年だけ／月まで／日まで／時刻まで
- あいまいさ：「〜頃」、「AとBの間のどこか」
- 日付がない出来事も、前後関係だけを線で示せる
- 分岐の長さ（体感時間）は、年・日・時間などの単位で入れる

## 6. 地図

- 自分で用意した画像を読み込み、その上に付箋をピンで留める
- 星系図のような宇宙規模の地図も、同じく画像として読み込む
- 地図の入れ子（世界 → 国 → 街）は作らない
- 時代による地図の変化と時系列マップの連動は、当面作らない（後から追加できる余地は残す）

## 7. 保存と同期

- アプリを開いたら Google でログインし、Googleドライブ上の世界（プロジェクト）を開く
- 世界ごとにドライブ上のフォルダを1つ作り、その中にデータと画像を置く
- 編集は自動でドライブに保存する
- オンライン専用。電波がないときは開けなくてよい
- PCとスマホで同じ世界を同時に開いている場合：保存するとき、もう一方の端末が先に保存していたら、その内容を取り込んでから保存する。同じ付箋を両方で直していたら、新しい方を採用する（仮決め）
- 変更履歴の機能は作らない。ただし、Googleドライブ自体にファイルの版の履歴があるので、いざというときはそこから戻せる
- データ量は「多いほどいい」。まずは世界ごとにデータを1ファイルにまとめる方式で作る。付箋が数千〜1万枚あたりで保存が遅くなるようなら、ファイルを分割する方式に切り替える

## 10. 進め方（Q34 への提案）

「動くものを使ってみないと断言できない」（Q7）という回答と、§8 の課題1〜3を踏まえると、次の2通りが考えられる。

| 案 | 内容 |
|---|---|
| ★A. 試作品が先 | 時系列マップだけの試作品を先に作る。保存なし、サンプルデータ入り（浦島太郎、パラドックスあり／なしのタイムトラベル、タイムループ、ドリームランド）。視点の切り替えによる歪み、空白の圧縮、カーソルでの日時表示を実際に触って確かめる。確かめ終わったら捨てる前提で作り、結果を設計に反映してから本体を作る |
| B. 土台が先 | 付箋・ボード・ドライブ保存の土台から作り、時系列マップは後で載せる |

- 推奨は A。一番の難所を最初に確かめておけば、本体の作り直しを避けられる
- 試作品は、このチャットから開けるWebページ（非公開のリンク）として渡す。PCでもスマホでも開ける

本体の作る順番（案）：

1. 付箋・線・コルクボード・テンプレート
2. Googleドライブ接続（世界を開く・自動保存）
3. 時系列マップ（試作品の結果を反映）
4. 暦（西暦 → 和暦 → ヒジュラ暦 → 架空の暦）
5. まとめ・グラフビュー・家系図
6. 地図
7. スマホ表示の調整
8. 見た目の仕上げ
9. （候補）マルコフ連鎖のランダムキャラクター
