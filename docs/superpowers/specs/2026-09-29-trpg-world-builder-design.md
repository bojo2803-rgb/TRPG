## 1. 目的

GM（自分）が TRPG の世界設定を作り、整理するための補助アプリ。

- メインで遊ぶシステム：クトゥルフ神話TRPG（CoC）
- まとめたい情報：NPC、時系列、ロケーション、アイテム、勢力、ストーリーの流れ
- 設定の自動生成はしない。ただし、発想のきっかけとして「マルコフ連鎖でランダムなキャラクターを出す機能」を後で追加する
  - 名前・能力値・メモ欄まで、すべてをランダムに出す
  - 出来が良すぎるとインスピレーションにならないので、**ガチランダム**でよい
- AIアシスタント連携は将来の構想。**今回は作らない**

## 3. 付箋とボード

### 3.1 付箋

- どんなアイデアでも書ける1枚。種類は固定せず、タグと色で整理する
- 書ける内容：文字、書式（見出し・太字・箇条書き）、画像、本文中から別の付箋へのリンク
- **テンプレート**：タグごとに決まった入力欄を持たせられる
  - 例：CoCの探索者・NPC用に、能力値、技能、所属、年齢、生年月日など
  - テンプレートは画面上で自分で作り、直せる（コード不要）
  - **CoC 6版**用のひな形を最初から用意する。ルールブックの本文は入れず、項目名と初期値の枠だけを用意する

### 3.2 線（付箋どうしのつながり）

- ラベル、色、線の種類（実線・点線など）を付けられる
- ボード上の線の矢印は「付けても付けなくてもいい」扱いにする（仮決め）
- 時系列マップの線には矢印を使わない（§4.1）

### 3.3 ボード

- ボードは自由に何枚でも追加できる
- キャラクター、出来事、ロケーション、シナリオなどの付箋は、**それぞれ専用のボードを持てる**。付箋を開くと、そのボードが出てくる
- 1枚の付箋を、いくつものボードに貼れる。中身は1つだけで、どこで直してもすべてに反映される
- ボードの種類：

| 種類 | 内容 |
|---|---|
| コルクボード | 付箋を自由に並べ、アイデアや概念を自由につなぐ |
| 家系図 | 親子・婚姻などの関係から、自動で家系図の形に並べる |

### 3.4 まとめ（親子関係）

- 付箋どうしに「親子」の関係を付けられる。シナリオ → 章 → 場面、のような入れ子に使う
- 親も子も何人いてもよい。循環（パラドックス）が起きてもよい
- ボード上でも、時系列マップ上でも使える。たためば1つにまとまり、ひらけば中身が見える
- たたむときの決まり（案）：たたんだまとめの子孫は隠す。ただし、別の開いているまとめにも属していれば表示する。循環していても無限にたどらないようにする

### 3.5 グラフビュー

- すべての付箋とつながりを、Obsidian のグラフビューのような網の目で表示する
- 親子関係のように、ピラミッド型では描けないつながりを見渡すのに使う

## 4. 時系列マップ

### 4.1 しくみ

時間は、点と線でできたノンリニアなグラフとして描く。

- **時点**：マップ上の点
- **時間の流れ**：時点と時点をつなぐ線。どの線も**左から右へ流れる**。矢印は使わない
- **本線**：暦と結びついた基準の線（西暦）
- 線の上にカーソルを合わせると、その位置の日時（西暦の年月日）が出る。分岐や逆行があっても、日時を見れば時間の流れがわかる

| 線の形 | 意味 |
|---|---|
| 本線から分かれて、後で本線に戻る | 体感時間の違い（浦島効果など） |
| 分かれたまま戻らない | 世界線の分岐 |
| 本線とつながらない別の線 | パラレルワールド、ドリームランドのような別の世界 |
| 分かれて輪になり、元の線に戻る線 | タイムループ（その期間を何周もくり返す世界線。ループに入る人物だけが周回し、入らない人物は元の世界線を進む。通る主体の視点では周回ごとにほどける。ループの中にもループを作れる） |
| 付箋の「<」の印 | 分岐点の出来事（ここで世界が分かれうる） |
| 過去・未来の時点へ渡る（◆） | タイムトラベル |
| 同じ瞬間のまま別の世界線・世界へ渡る（◆） | 移動（瞬間移動・世界線の出入り） |
| 同じ時間を2回通る | 自分が重なる（タイムターナー。同じ時間にもう一人の自分がいる） |

### 4.2 時間の長さの表し方

- **宇宙の始まりから**すべてを表せる
- 何も起きていない区間は、どれだけ長くても短く縮めて描き、「≈ 92億年」のような省略の印を付ける。どの主体の視点でも同じ
- 最小の単位は「分」。記録の仕組みは秒にも対応させておき、必要になったら画面に出す（§5.4）

### 4.3 主体と視点の切り替え（歪み）

「動くものを使ってみないと断言できないが、合っていると思う」との回答。**試作品で確かめる**（§10）。

- どの付箋も「主体」になれる。主体は、時系列マップ上で自分が通った**道筋**を持つ
- 主体を選ぶと、世界線を切り分けて、その主体が体験した区間を体験した順に**中央の1本**につなぐ。主体が通らなかった部分は、切れ目から斜めに分かれて上下の段に退き、次の切れ目で斜めに戻る（第1版の感想「本線などが分断されて前後にくっつく」による。試作品 第2〜6版）
- 全体は画面に残したまま、1回のなめらかな動きで変形する
- 線の長さは、付箋の数と、重要な出来事どうしの間の時間の桁で決まる（§10 第5版）
- **斜めの線は、分かれたこと・戻ったことを見せる演出で、時間は流れない**（第7版）。斜めの線は「すき間」に置き、斜めの線の両端は同じ日時。本線の視点では、分かれた世界線がいちばん長いときは、そのあいだの本線もその長さまで伸びる（竜宮にいるあいだの本線は、竜宮より短くならない）
- 通らなかった部分は、両側の切れ目のあいだに収め、両側とも斜めの線でつなぐ。点線でつなぐのは、体験の順が時間の順と逆になって、両側の斜めの線が引けないときだけ（第7版）
- **どの視点からどの視点へ移るときも、同じ決まりで動く**（第7版）。線・輪・付箋・文字・斜めの線・◆のそれぞれに、視点が変わっても同じ名前を付けて突き合わせ、両方にあるものは画面上の位置から位置へまっすぐ動かし、片方にしかないものは同じ速さで薄れる・現れる。A→B の途中の絵と、B→A を同じだけ戻った途中の絵は同じになる（自動確認で、見本のすべての視点の組み合わせ138通りで一致）
  - 分岐点は、そこから出る斜めの線と、その前後の線が名前で結ばれているので、切り替えのあいだも一緒に動く（分岐点が動きの基準になる）
- 何も選んでいないときは、本線の視点

```
[本線の視点] 本線がまっすぐ
 700 ── 720 ────── 300年 ────── 1020 ── 1070
           ╲                  ╱
            ── 竜宮城（3年）──          ← 分岐点から斜めに分かれ、合流点へ斜めに戻る

[浦島太郎の視点] 本人が体験した順に1本
 700 ── 720 ◆ 竜宮城（3年） ◆ 1020 ── 1070
           ╲                  ╱
            ── 本線の300年 ──           ← 通らなかった部分は、切れ目から斜めに退く
```

- 当初の案（縮んだ線は波線、伸びた線は色を変える）は、第1版の感想で上の形に変えたため使っていない

- 配置はすべて自動。**手で位置を直す必要がないように作る**

### 4.4 タイムトラベルとパラドックス

- パラドックスが起きる世界観と起きない世界観の、どちらも使えるようにする（第7版で決定）。そのために**分岐点の出来事**を用意できる（付箋に「分岐点」の印を付ける）。起きる世界観なら、分岐点から世界線を分け、起きない世界観なら分けない。分岐は自動では作らない
- 過去に戻ってパラドックスが起きた場合は、そこで世界線が分岐する
- パラドックスが起きなければ、同じ世界線の同じ時期をもう一度生きる。これは「自分が重なる」時間で、ループとは別の現象（試作品 第6版で決定）
- タイムループは**世界線として扱う**（第7版で決定）。元の世界線から分かれて、同じ期間を n 周くり返し、終わりで元の世界線に戻る。ループを作るときに、その期間に元の世界線にいる人物が自動で候補に出て、ループに入る人物を選ぶ。入らない人物は元の世界線をそのまま進む
  - ループの中でさらに小さなループを作れる（「元のループの何周目から分かれるか」を持つ）
  - 周回ごとの出来事は、1周目の出来事のコピー。周ごとに書き換える・その周では起こらないようにする・その周だけの出来事を足すことができる
  - 1周目の出来事は、ループを作ったときの元の世界線の出来事のコピー。ループの中のループなら、元のループのその周の出来事のコピー
  - ループの中へのタイムトラベルは「どの世界線の、どのループの、何周目の、何時」へ跳ぶと指定する
- 主体の区間どうしの移り方（タイムトラベル／移動）は、区間から自動で決まる（§10 第6版）
- **イースターエッグ**：パラドックスが起きそうな状況で、映画のセリフ風の警告を出す（例：「気をつけろ、マーティー！」）

### 4.5 同じ人物が2人いる場合

- 分身や、並行世界の同一人物は、「NPC1A」「NPC1B」のように別々の人物（別々の付箋）として扱う
- **分岐で2人に分かれる人物**（第7版で決定）：分岐の前から続く本人はそのまま進み、分岐した先に分身が現れる。分岐する世界線を作るとき、分かれる瞬間に元の世界線にいる人物を自動で候補に出し、分かれる人物を選ぶ。分身は分かれる前の人生を本人と共有するので、2回入力しなくてよい
- **意識だけの移動**（タイムリープ・心の入れ替わり）は、別の世界線として描けばよい（第7版で決定。作りの変更はない）
- タイムトラベルで同じ時間を2回通る場合は、1人の主体のまま「自分が重なる」時間として描く（タイムターナー。§4.4）

### 4.6 絞り込み

- あるタグの付いた要素を除外する／そのタグだけを表示する
- 選んだ主体に関係するものだけを表示する
- 期間で絞る
- キーワード検索で該当箇所を光らせる
- 世界線ごとに表示／非表示を切り替える

## 5. 暦と日付

### 5.1 基本方針

- **基本は西暦で表す**
- 出来事ごとに、その性質に合わせて別の暦を追加して表示できる（例：昔の日本の事件には和暦を追加）。すべての出来事にすべての暦を載せることはしない
- 日付はどの暦でも入力できる。入力に使った暦は、自動でその出来事の追加暦になる
  - 例：史料に「天正10年6月2日」とあれば、和暦のまま入力する。西暦（ユリウス暦1582年6月21日）に正しく変換され、和暦も併せて表示される
- 正確さにこだわる理由：昔の日本の出来事は太陰太陽暦（旧暦）で記録されていることが多く、変換がずれると西暦で並べたときに前後関係が崩れるため
- 正解が1つに決まらない日付は、黙ってどれか1つを選ばず、そう表示する
- 公表されている対照表と突き合わせるテストを作る
- ブラウザに入っている暦変換は、正確さの根拠にしない（明治5年以前の和暦を太陽暦の月日のまま出してしまう。新しい日付の仕組み Temporal は、調査時点の Safari では試験版のみ）。変換は自前で作り、ブラウザ内蔵の変換はテストの答え合わせにだけ使う

### 5.2 使える暦

| 暦 | 時期 |
|---|---|
| 西暦 | 最初から |
| 和暦（元号＋旧暦） | 最初から |
| ヒジュラ暦 | 最初から |
| 架空の暦（独自の月名・月数・日数・曜日・紀元） | 自分で追加できるようにする |
| そのほか（§5.5 (d)） | 必要になったら追加 |

各暦の流派は §5.5 の★（推奨案）を初期設定にする。**流派はすべて選べるようにし、よく使われる順に並べる**（第7版で決定）。

**分岐した時間の暦**
- 浦島効果などで引き伸ばされた分岐の中では、分岐した時点から西暦を数え直し、「**西暦;竜宮 722年**」のように分岐の名前を付けて表記する（「;」はシュタインズ・ゲートのイースターエッグ）
- 例：竜宮城の分岐（本線の720年に分岐し、1020年に合流、体感3年）の中では「720年〜723年」と数え、別の表記を付けて本線の西暦と区別する

**ドリームランド**
- 現実とは時間の流れ方が違う別の世界として、専用の暦を持たせる
- 現実の時間との対応は一対一ではない。ドリームランドの線は本線とつながらない別の線にし、夢見る者が出入りした時点だけが現実とつながる

### 5.3 時刻とタイムゾーン

- 時刻は分まで入力できる
- タイムゾーンを使える。初期設定は**日本標準時**
- 出来事ごとにタイムゾーンを指定できる（例：ロンドンの事件はロンドン時間で入力・表示）
- 歴史上の時差（日本標準時ができる1888年より前の地方時など）は、国際的に使われているタイムゾーンのデータベースに従う。そのデータベースが扱える範囲より前（数十万年より前など）は、決まった時差で計算する

### 5.4 内部の記録方法

- 日時は「**日の通し番号（整数）**」と「**その日の中の秒数（整数）**」の2つの数で記録する
  - 画面は分単位で表示する。秒を表示したくなったら、画面を変えるだけで済む
- この方式なら、宇宙の始まり（約138億年前）の日付でも秒まで正確に持てる
  - 1つの数で秒まで数えようとすると、ブラウザで正確に扱える数の上限を超える
- 暦の変換は、極端に大きい年（紀元前138億年など）でも正しく計算できるように作る

### 5.5 暦ごとの選択肢

各暦について、正確に決まる範囲と、流派が分かれる点を挙げる。★は推奨案で、初期設定にする。

#### (a) 西暦

| 論点 | 選択肢 |
|---|---|
| ユリウス暦とグレゴリオ暦の切り替え | ★A. 1582年10月15日で切り替え（歴史学の一般的な慣例）<br>B. 国・地域ごとの切り替え日を選べる（イギリス1752年、日本1873年、ロシア1918年、ギリシャ1923年など）<br>C. 全期間グレゴリオ暦で計算（先発グレゴリオ暦。ISO 8601 と同じ）<br>D. 全期間ユリウス暦で計算 |
| 紀元前の数え方 | ★A. 歴史式（紀元前1年の次が紀元1年。0年はない）<br>B. 天文式（0年があり、紀元前1年＝0年、紀元前2年＝−1年） |
| 年の始まり | ★A. 1月1日<br>B. 地域の旧習に合わせる（例：イングランドは1752年まで3月25日が年始）。この場合「1714/15年」のように二重に表記する |

計算だけで正確に出せる。流派の違いはあっても、流派を決めれば答えは1つに決まる。

#### (b) 和暦（元号＋旧暦）

期間ごとに、正確さの根拠が違う。

| 期間 | 根拠 | 正確さ |
|---|---|---|
| 明治6年（1873年）以降 | 元号＋グレゴリオ暦 | 計算で正確 |
| 7世紀末〜明治5年 | 実際に使われた暦法（元嘉暦・儀鳳暦・大衍暦・五紀暦・宣明暦・貞享暦・宝暦暦・寛政暦・天保暦）による暦日。専門家が編纂した対照表（内田正男『日本暦日原典』1975年が標準）に基づく | 対照表どおりなら正確 |
| それより前（神武天皇〜） | 『日本書紀』の日付を、後の時代の暦法でさかのぼって計算した復元（小川清彦の研究）。**史実ではなく伝承上の暦日** | 復元値 |

データの入手元の選択肢：

| 案 | 内容 | 注意点 |
|---|---|---|
| ★A | jcalendaR（和暦・旧暦・西暦を相互変換するRのパッケージ。MITライセンス）のデータを使う | データの出典を確認する必要あり |
| ★B | 国立天文台「日本の暦日データベース」（神武天皇〜）を参照して表を作る | 利用条件の確認が必要 |
| C | 各暦法の計算式を自分で実装する | 手間が非常に大きく、検証も難しい |
| D | 書籍（『日本暦日原典』など）から手で入力する | 現実的ではない |

推奨：A か B を元データにし、もう一方と突き合わせて検証する。

そのほかの論点：

| 論点 | 選択肢 |

## 7. 保存と同期

- アプリを開いたら Google でログインし、Googleドライブ上の世界（プロジェクト）を開く
- 世界ごとにドライブ上のフォルダを1つ作り、その中にデータと画像を置く
- 編集は自動でドライブに保存する
- オンライン専用。電波がないときは開けなくてよい
- PCとスマホで同じ世界を同時に開いている場合：保存するとき、もう一方の端末が先に保存していたら、その内容を取り込んでから保存する。同じ付箋を両方で直していたら、**同じ付箋が2枚現れる**（どちらを残すかは自分で決める）
- 直前の操作の取り消し（Ctrl+Z）を作る
- 変更履歴の機能は作らない。ただし、Googleドライブ自体にファイルの版の履歴があるので、いざというときはそこから戻せる
- データ量は「多いほどいい」。まずは世界ごとにデータを1ファイルにまとめる方式で作る。付箋が数千〜1万枚あたりで保存が遅くなるようなら、ファイルを分割する方式に切り替える

## 10. 進め方（決定：A. 試作品が先）

「動くものを使ってみないと断言できない」（Q7）という回答と、§8 の課題1〜3を踏まえると、次の2通りが考えられる。

| 案 | 内容 |
|---|---|
| ★A. 試作品が先 | 時系列マップだけの試作品を先に作る。保存なし、サンプルデータ入り（浦島太郎、パラドックスあり／なしのタイムトラベル、タイムループ、ドリームランド）。視点の切り替えによる歪み、空白の圧縮、カーソルでの日時表示を実際に触って確かめる。確かめ終わったら捨てる前提で作り、結果を設計に反映してから本体を作る |

- 推奨は A。一番の難所を最初に確かめておけば、本体の作り直しを避けられる
- 試作品は、このチャットから開けるWebページ（非公開のリンク）として渡す。PCでもスマホでも開ける

### 試作品

- ファイル：`prototype/timemap.html`（捨てる前提。本体には流用しない）
- 第4版から画面で編集でき、編集内容はブラウザの中に保存する
- 第7版から、世界のデータ（基本のサンプルと作例の物語）はプログラムに書かず、`prototype/examples/` のファイルに置く（一覧は `index.json`）。試作品は情報を見せるだけのもの

**初版で試したこと**
- 主体の生涯線を別に引き、世界線を伸び縮みさせて合わせる方式
- 線の長さは時間の長さ（何もない区間は対数で圧縮）

**初版への感想**
- 線の長さは、主体が体験する**情報量**に比例させてほしい
- 本線などが**分断されて、前後にくっつく**イメージだった
- アニメーションのつながりが弱い。どの線がどこから来たか、もっとわかるようにしてほしい

**第2版のしくみ**
- 線の長さ＝付箋（情報）の数。何も起きない区間は、何億年あっても最小の長さになる。実際の年数は線の下に「≈」で書く
  - 付箋を絞り込んだり、まとめをたたんだりすると、線もその分短くなる
- 主体を選ぶと、世界線を切り分けて、主体が体験した区間をその順番で中央に1本につなぐ（区間どうしのつなぎ目は◆）
- 主体が通らなかった残りは上下の段に退け、切れ目のすぐ後ろ（後ろがなければ手前）にくっつける。切れ目とは細い点線でつなぐ
- 同じ時間を2回目以降に体験した区間は、中央の線に点線の複製として並べ、本来の位置と細い線でつなぐ。その区間の付箋も薄い複製で出す
- 主体が一度も通らない世界線は、分岐・合流・夢との出入りなど「同じ瞬間」のつながりで位置を合わせる
- アニメーションは3段階（通らない部分がどく → 横に滑る → 体験した部分が中央にはまる）。動いている間は元の位置に薄い跡を残す
- 線にカーソルを合わせる（スマホはタップ）と、同じ世界線の破片がすべて光り、ほかは薄くなる
- 自動確認：暦の計算、各世界線が破片で過不足なく覆われること、どの破片も左から右へ流れること、中央の線が体験した順に並ぶこと、付箋を減らすと線が短くなること

**第2版への感想**
- 3段階のアニメーションではなく、1つのなめらかな動きにしてほしい。動いている間に付箋の文字や斜めの線が消えるのも困る
- ループは、線の上に輪があって、ループする主体に焦点を当てると輪が展開されて線になるイメージ
- 焦点を当てた主体の線を、アニメーションの後に画面の真ん中へ。焦点を示す、左右を貫く横線がほしい
- ドラッグすると文字が選択されてしまう
- 長さは情報量を極力変えずに、時間が10倍になるごとに1伸びるようにしたい（単位と重みの配分は任せる）

**第3版のしくみ**
- 長さ＝最小の幅0.3 ＋ 付箋1枚につき4 ＋ 時間が10倍になるごとに1（1日を単位に数える。10日で1、100日で2、約27年で4、138億年で約12.7）
  - 区切りにするのは、付箋・つながり・いまの主体の区間の境目・世界線の端だけ。ほかの主体の誕生日などで区切ると、区切りが多いほど長くなってしまうため
- アニメーションは1回のなめらかな動き。付箋・つながりの線・線の名前も、線と一緒に動く。段の割り当ては動いた後の位置で決めておき、途中で段が入れ替わらないようにする
- ループは線の上の輪として描く（横には進まない）。ループする主体を選ぶと輪がほどけて線になり、2周目以降の複製も輪からほどけ出てくる
- 焦点を当てた線は画面の縦の真ん中に来る。その高さに、左右を貫く横線を引く
- ドラッグで文字が選択されないようにした。スマホでは凡例をたたむ

**第4版：編集できるようにした**（「編集の操作感を試したい」という要望）
- 付箋：追加・編集・削除。名前、タグ、世界線、日時、まとめ（新しいまとめもその場で作れる）
- 世界線：追加・編集・削除。暦は「西暦系（「西暦;名前」と表示）」か「架空の暦（1年＝12か月×30日、月の名前を付けられる）」。作るときに「別の世界線から分かれる点」「合流する点」も指定できる
- つながり：分岐・合流・世界線の出入り・時間移動（パラドックスあり／なし）・ループ
- 主体：区間（どの世界線の、いつからいつまで）を体験した順に並べる。いま選んでいる主体は、その場で編集できる
- 線をクリック（タップ）すると、その日時に「付箋を足す／ここから分かれる世界線を作る／ここからつながりを作る／この世界線を編集」のメニューが出る。付箋・つながり・つなぎ目（◆）をクリックすると編集画面が開く
- 日時の入力：西暦（紀元前も可）か「〜年前（年・万年・億年）」。存在しない日付（2月30日、1582年10月5〜14日など）や、世界線の範囲外の日時は、理由を示して保存しない
- 削除は、ボタンを2回押して確定する。使われている世界線は削除できない（理由を表示）
- 元に戻す（Ctrl+Z）、サンプルに戻す
- 編集内容は、試作品ではこのブラウザの中にだけ保存する（本体ではGoogleドライブに保存する）
- 自動確認：上の内容に加えて、入力欄の値と日時の往復、存在しない日付の拒否、画面からの編集の一連の流れ（付箋追加 → 元に戻す → 分岐する世界線の追加 → 主体の追加 → ループの追加 → 再読み込みしても残る → サンプルに戻す）

**第4版への感想（編集機能の前に直す点）と、その対応**
- すべての視点移動を同じ動きにしてほしい → 動く前の画面上の位置から、動いた後の画面上の位置へ、すべての線と付箋をまっすぐ同じ速さで動かす方式に統一した（拡大率と位置を別々に動かしていたせいで、右に行きすぎてから戻る動きになっていた）
- 視点を移すとき、つながりの点線がいきなり消える → 点線の両端が近づいて縮みながら、つなぎ目（◆）に変わる。逆向きでは◆がほどけて点線になる。切れ目のつながりの点線も、伸びて現れ、縮んで消える
- ループを開くときと閉じるときの動きが違う → 開くときは輪がほどけ、2周目以降の複製が輪から出てくる。閉じるときはそのちょうど逆
- ズームアウトが速すぎて見切れる → 画面上をまっすぐ動くので途中で大きく飛ばない。動く時間を1.1秒から1.5秒にした
- 長さの疑問（竜宮の3年と本線の300年で差がつきすぎる） → ひと続きの線の長さ = 最小の幅0.3 + 付箋の数（1枚につき1） + その線全体の時間の桁（1日を単位に、10倍ごとに1）。付箋と付箋のあいだの時間の桁を足すことはしない。線の中の位置は時間の流れに比例させる
  - 浦島太郎の視点で、竜宮の3年 = 0.3 + 3 + 3.04 ≈ 6.3、本線の720〜1020年 = 0.3 + 5.04 ≈ 5.3
- 自動確認：上の長さの例と、すべての視点の組み合わせで移動の途中の描画が壊れないこと

**第5版：重要な出来事で長さを区切る・誕生を主体へ・一覧・2回クリックのつながり**
- 長さ：重要な出来事から次の重要な出来事までを1区切りとし、区切りの長さ = 最小の幅0.3 + 区切りの中の付箋の数 + 区切りの時間の桁（1日を単位に、10倍ごとに1）
  - 重要な出来事：主体の誕生、分岐・合流・世界線の出入り・時間移動、ループの始まりと終わり、シナリオ（まとめ）の最初と最後、世界線の端
  - ふつうの付箋は区切りを作らない（副次的なもの）。区切りの中では時間の流れに比例した位置に置き、1枚につき幅1を足す
- 誕生は主体の編集にまとめた。主体の最初の区間の始まりが誕生で、「〇〇 誕生」の付箋は自動で出る（クリックで主体の編集）
- 見つかった不具合と修正：
  - 本線（客観）の視点で、竜宮にいた間の本線（720〜1020年）の長さがほぼ0だった → 区切りごとに時間の桁を数えるようにして解消（約5.3）
  - βから本線へ戻るつながりを足すと、βの時系列の順番が本線とずれて見えた → 主体が通らない世界線のうち、本線と同じ時計のもの（西暦系で、分岐・合流が同じ日時どうし）は本線の同じ日時の位置にそろえる。時計が違うもの（竜宮・夢など）は、分岐・合流・出入りの点を相手に合わせ、そのあいだに収める
- ループ：主体の区間を「ループを回る」にして、ループと周回数を選ぶ（少女をもう1周させるなら周回数を増やすだけ）。周回の区間は、ループの始まりと終わりの日時を正確に使う

- つながり：出発点と到着点を順にクリック（線の上ならその位置の日時、付箋ならその付箋の日時）すると仮置きされ、すぐ編集画面が開く。線のメニューの「ここからつながり」は、出発点を置いた状態から始まる

**第5版への感想と、第6版での対応**
- 竜宮にいる長さを伸ばしても、出来事の間隔が変わらない
  - 原因：竜宮の滞在が「世界線の範囲」「合流のつながり」「主体の区間」の3か所に別々に書かれていて、1か所を直してもほかが古いまま残った。特に古い合流点（竜宮723年）が重要な出来事として残り続け、長さの区切りと位置合わせの錨になっていた
  - 対応：分岐・合流を世界線の性質（始まり・終わり）にした。世界線の端を動かすと、分岐点・合流点も、端にいた主体の区間と付箋も一緒に動く。主体の区間を世界線の外まで延ばすと、世界線も延びる
- 主体の区間どうしのジャンプを自動で割り当てる
  - 移り方は2種類。「タイムトラベル」（同じ時計で、時間が違う所へ）と「移動」（瞬間移動・世界線の出入り。同じ瞬間のまま。二つは同じことなので統合した）
  - 判定：分岐・合流をたどる、または同じ時計で同じ瞬間 → 移動。同じ時計で時間が違う → タイムトラベル。時計を比べられない世界（夢など）への出入り → 移動
  - 同じ時計：西暦系で、分岐・合流の両側の日時がそろっている世界線どうし（世界線βは本線と同じ時計。竜宮は合流の日時がずれるので別の時計）
  - 主体の編集で、種類の上書き・名前・パラドックスを書き足せる。手で作る「時間移動」「出入り」のつながりはなくした（区間から決まるので、ずれようがない）
- 世界線の分岐を分岐らしく：分かれた世界線は分岐点から斜めに分かれ、合流点へ斜めに戻る（45度。短いときは急に）。主体が通らなかった残りも、切れ目から斜めに分かれて斜めに戻る。とても短い残りは、とがらないよう浅いくぼみにする
- 「ここから延ばす」を強化（クリックで編集はそのまま）
  - 付箋を引っぱって、何もない所で離す → そこから分かれる世界線（離した高さで本線の上か下か）
  - 別の点で離す → 「つなぐ」メニュー：主体がここから行き先へ移る／このあいだをループにする／ここで分かれて行き先で合流する世界線
  - 「＋ つなぐ」ボタン（2回クリック）と、線のメニューの「ここからつなぐ」も同じメニューになる。主体が移る案は、保存前の案として主体の編集画面に開く
- ループと「自分が重なる」は別の現象
  - ループ：つながりの一種として残し、「世界線のこの期間を n 周くり返す」とした。この期間を通る主体は周回を全部体験し、その主体の視点では周回ごとにほどける（○が折り返し）
  - 同じ場所・同じ時間を2回通る（タイムトラベルで戻るなど）のは「自分が重なる」時間（タイムターナー）。点線の複製と、1回目への細い点線で描く
  - ループの中へのタイムトラベルは、行き先を「世界線・日時・何周目」で指定する（主体の区間の「入った」に何周目を入れる）。サンプルに観測者O（2085年から、ループの2周目の夏祭りへ跳び、3周目を経て、出発した瞬間へ戻る）を足した
- 表記の矛盾（Rが目覚めてから「≈17年」「≈18.6年」と出る、眠っていた間に本線でどれだけ経ったかわからない）
  - 原因：線の下の「≈」は、目に見えない時点（Rの人生の終わりなど、付箋も印もない点）でも区切られていた。さらに1年未満は出さない決まりだった
  - 対応：「≈」は、目に見える印（付箋・分岐や移動の端・ループの端・破片の端）から次の印までの、その世界線の時間。分・時間・日も、文字が入れば出す。線の名前にも破片の長さを付けた（例：本線 1920年3月1日 23:00〜3月2日 7:00（8時間））。カーソルを合わせると、前後の印のあいだの時間も出る
  - タイムトラベルには跳んだ時間を「≈30年前へ」のように出す（Mの1985年→1955年は約30年）。移動（同じ瞬間）には出さない。時計を比べられない世界どうしにも出さない
- 別バージョン：世界線が分かれた瞬間の、分岐元の出来事と、分岐先で同じ瞬間に起きた出来事が対になる
  - 付箋の編集画面から「＋ ここで世界線を分けて、別バージョンを書く」「＋ 世界線βに別バージョンを書く」で書ける。対になった出来事は、編集画面・カーソル・一覧に「別バージョン」として出る
  - 分岐の瞬間の付箋から引っぱって分岐を作ると、別バージョンの名前の欄が最初から埋まっている
  - サンプル：本能寺の変 → 世界線γ「本能寺の変（信長が脱出する）」
- 前の版で保存したデータは、分岐・合流のつながり → 世界線の分岐・合流、ループのつながり → ループ（回数は回っていた主体の周回数）、時間移動・出入りのつながり → その区間の移り方の名前とパラドックス、に直して引き継ぐ。主体の区間にないつながりは捨てる
- 自動確認：竜宮の滞在を延ばすと間隔が変わって合流点がそろうこと（世界線の編集からも主体の編集からも）、移り方の自動判定、跳んだ時間、ループの周回と重なりの区別、途中の周への移動、別バージョン、「≈」の区切り、引っぱって延ばす操作、第5版のデータの読み込み

**第6版への要望と、第7版での対応**
- 世界のデータをHTMLに書かない（「このプログラムはあくまで一連の情報の視覚化でしかない」）

- 斜めの線の上で時間が進まないように：分岐・合流・移り方の斜めの線と◆は、時間の流れない「すき間」に置く
  - 本線の視点：分岐元・合流先の線に「すき間の点」を足し、「同じ瞬間は同じ位置」「分かれた線の始まりは分岐点のすき間の後」「合流する線の終わりは合流点」と決めて、いちばん長い道のりで位置を決める。そのあいだは自分の長さの割合で並べる
  - 主体の視点：移り方（◆）とループの折り返し（○）の所にすき間を入れる。通らなかった残りは、両側の切れ目のあいだに収める。短い所は、すき間を縮めてでも両側に斜めの線を入れる
- 本線の視点で、浦島太郎が竜宮にいるあいだの本線の長さが、竜宮と合わない → 上のいちばん長い道のりの決め方で、本線は竜宮より短くならない
- 浦島太郎の視点で、本線の残り（720〜1020年）が、出ていく側は斜めの線なのに、戻る側は点線だった → 両側の切れ目のあいだに収め、両側とも斜めの線にした
- 本線から別の視点、別の視点から別の視点、別の視点から本線で、アニメーションが違う → 動く前の場面と動いた後の場面を、部品ごとに名前で突き合わせる1つの決まりにした（§4.3）。どの向きでも同じ動きになることを、見本の物語すべての視点の組み合わせで自動確認した
  - 主体の視点に移ると「この主体を編集」ボタンが現れてボタンの列が折り返し、地図の高さが変わって絵がずれていた。ボタンは隠さずに押せない状態にした
- ループを世界線にした（§4.4）。サンプルでは、ループする少女だけが夏休みのループに入り、時間旅行者Mは入らない。少女は3周目の中で「同じ一日のループ」を3周する
  - 輪は、線の真ん中に輪をひとつ下げた形で描く（線の長さ＝時間の長さは変えない）。周回をほどくときは輪が縮んで線になる
- 周回ごとの出来事：ループの周回の付箋をクリックすると「すべての周／この周だけ書き換える／この周では起こらない」を選べる。周回の線から付箋を足すと「すべての周／この周だけ」を選べる。2周目以降のコピーは薄く、書き換えた周とその周だけの出来事は濃く出る

- 段：上下の段は、横に重ならなければほかの世界線と同じ段に入れる。段が多いときは画面の高さに収まるよう段の間を詰め、はみ出すときだけ縦にずらす。付箋は、別の段の付箋とも重ならないよう積む
- 前の版（第6版まで）のデータ：ループの期間は「分かれて戻るループの世界線」になり、その期間を通っていた主体はループを通る（第6版まではだれでもループした）。その期間の付箋はループへ移る
- 自動確認：見本すべての視点で配置の決まり（世界線を過不足なく覆う・左から右・中央の線の順・斜めの線の両端が同じ日時）、浦島太郎の視点の両側の斜めの線、本線の視点の竜宮の長さ、ループの周回と入る人物、周ごとの出来事、ループを作る・人物を外す・ループの中のループ、周ごとの書き換え、分岐点、分身、書き出しと読み込み、見本を開く・元に戻す、開いて保存しただけでデータが変わらないこと、第6版のデータの読み込み、スマホの画面、切り替えの向きによらない動き（138通り）と、動き始め・動き終わりで絵が飛ばないこと
